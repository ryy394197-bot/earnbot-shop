Title: 「下午做完一個 CLI：開源 Python 產品的實戰經驗分享」
Subtitle: 不需要花費大量時間和金錢，就能做出一款功能完整的 CLI 工具。
Intro:
最近在個人專案中，我花了大約 2-3 小時開發了一個簡單但功能完整的 Python 命令列介面 (CLI)。當時並沒有預期要開源它，但後來發現這個工具非常有用，因此決定把它分享給更多人使用。
在這篇文章中，我將分享如何在下午的時間內完成一個 CLI 工具，並且為這個工具撰寫完整的使用手冊供他人參考。如果你也想自己開發一款 CLI 工具，請跟我一起看看如何做到。
Actionable sections:
1. 建立專案目錄與檔案結構
首先，你需要決定要開源的工具是用來解決什麼問題。接著，建立一個專案目錄並設定基本檔案結構：README.md、requirements.txt 和 src/ 目錄 (包含你的主要程式碼)。
我建議使用 Git 控管專案，並在 GitHub 上創建一個新的 repo。GitHub 是一個很好的平台，可以讓你方便地分享和追蹤開發進度。
2. 優化代碼與效能
為了確保 CLI 工具能夠快速執行，你需要優化你的程式碼以及考量效能問題。你可以使用工具如 PyLint、PyChecker 和 PyTest 來檢查程式碼品質並進行測試。
如果你的 CLI 工具需要處理大量資料或需要較高的運算效能，你可能需要考慮使用多線程或多執行緒 (threading) 或者異步函式庫 (asyncio)。在這邊，你可以利用 Python 的 asyncio 模組來實現。
3. 使用標準輸入與輸出
如果你的 CLI 工具會接收使用者輸入或顯示結果給使用者，你需要使用 Python 的標準輸入 /輸出功能。你可以在你的程式碼中加入函式來處理這些輸入和輸出。
例如，你可以使用 input() 函式來取得使用者輸入，並使用 print() 函式來顯示訊息。如果你需要將資料寫入檔案或從檔案讀取資料，可以使用 Python 的內建模組如 os、sys 和 pathlib 進行操作。
4. 優化錯誤處理與日誌記錄
為了確保 CLI 工具能夠穩定運作並提供良好的使用者體驗，你需要優化錯誤處理和日誌記錄。你可以利用 try/except 區塊來捕捉程式中的異常，並使用 logging 模組來記錄錯誤訊息。
另外，在你的程式碼中加入一些提示或警告訊息也是很重要的，這樣可以讓使用者知道他們需要做什麼才能解決問題。
5. 設定 CLI 命令與參數
在這個步驟中，你需要設計 CLI 命令和相對應的參數。你可以使用 argparse 模組來設定命令列介面的參數格式。
例如，你可以在你的程式碼中加入以下代碼：
```python
parser = argparse.ArgumentParser()
parser.add_argument('--input', type=str, help='Input file path')
parser.add_argument('--output', type=str, help='Output file path')
args = parser.parse_args()
```
這段程式碼會讓使用者在執行 CLI 工具時可以輸入兩個參數：--input 和 --output。當使用者使用這些參數時，你的程式將會從指定的檔案讀取資料並寫入另一個檔案。
Common mistakes:
1. 不該開源就開源
如果你沒有充分思考過這個工具是否真的有用，並且不確定它是否有足夠的價值可以分享給他人，那就不需要急著把它開源。在開源之前，請確保你的工具具有獨特的功能或者解決了一個重要的問題。
2. 代碼品質不佳或結構雜亂
如果你的程式碼品質不高或是檔案結構混亂，可能會讓使用者感到困惑並影響他們使用你的 CLI 工具的能力。因此，在開發過程中要注意保持良好的程式碼品質和清晰的檔案結構。
3. 沒有提供足夠的使用手冊
當你開源一個 CLI 工具時，你需要為它撰寫完整的使用手冊。這可以幫助使用者更容易地了解如何使用你的工具以及解決可能遇到的問題。你可以利用 Markdown 格式來撰寫手冊。
4. 沒有考慮到錯誤處理和日誌記錄
如果你的 CLI 工具沒有妥善處理錯誤或沒有提供足夠的日誌記錄，可能會讓使用者感到沮喪並影響他們的信任感。因此，在開發過程中需要仔細考慮這些問題。
